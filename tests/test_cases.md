# 测试用例文档

## 1. 配置参数收发功能测试

### 1.1 发送配置参数

#### 测试场景 1：正常发送配置
- **测试ID**：TC-CONFIG-SEND-001
- **测试目的**：验证服务器能够正确接收和处理配置参数
- **测试环境**：
  - 后端服务器运行中
  - 前端可访问
- **测试步骤**：
  1. 构建包含完整配置参数的JSON请求
  2. 向 `/api/config/send` 端点发送POST请求
  3. 检查响应结构和内容
- **测试数据**：
  ```json
  {
    "ip_address": "192.168.1.100",
    "username": "chano",
    "config": {
      "batchSize": 2,
      "inputSize": 224,
      "threads": 4,
      "precision": "int8",
      "confidence": 0.6,
      "iou_threshold": 0.4,
      "max_age": 35,
      "min_hits": 4,
      "fps_limit": 30
    }
  }
  ```
- **预期结果**：
  - 响应状态码：200 OK
  - 响应结构包含 `success`、`error`、`message` 字段
  - 路径构建正确，包含用户名

#### 测试场景 2：缺少配置数据
- **测试ID**：TC-CONFIG-SEND-002
- **测试目的**：验证服务器能够处理缺少配置数据的情况
- **测试环境**：
  - 后端服务器运行中
- **测试步骤**：
  1. 构建缺少 `config` 字段的JSON请求
  2. 向 `/api/config/send` 端点发送POST请求
  3. 检查响应结构和内容
- **测试数据**：
  ```json
  {
    "ip_address": "192.168.1.100",
    "username": "chano"
    // 缺少 config 字段
  }
  ```
- **预期结果**：
  - 响应状态码：200 OK
  - 响应 `success` 字段为 `false`
  - 响应包含错误信息："Configuration data is missing"

#### 测试场景 3：使用自定义根目录
- **测试ID**：TC-CONFIG-SEND-003
- **测试目的**：验证服务器能够处理自定义根目录参数
- **测试环境**：
  - 后端服务器运行中
- **测试步骤**：
  1. 构建包含 `root_dir` 字段的JSON请求
  2. 向 `/api/config/send` 端点发送POST请求
  3. 检查响应中的路径信息
- **测试数据**：
  ```json
  {
    "ip_address": "192.168.1.100",
    "username": "chano",
    "root_dir": "/custom/path/to/project",
    "config": {
      "batchSize": 1
    }
  }
  ```
- **预期结果**：
  - 响应中使用自定义根目录路径
